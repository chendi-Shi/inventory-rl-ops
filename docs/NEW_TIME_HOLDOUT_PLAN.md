# Frozen-policy M5 future-period check: days 1914–1941

This protocol is committed **before** this project downloads or inspects `sales_train_evaluation.csv`. All prior reported tests end at day 1913. Kaggle's M5 evaluation file extends the same item/store daily sales series through day 1941. The two previously released policy bundles are already fixed: `models/wi1-policy-search` and `models/tx3-context`. This check adds a new **28-day calendar period** without training, tuning, changing model activation, or selecting favorable stores after seeing outcomes. It is still a retrospective simulation using observed sales as a demand proxy and synthetic economics.

## Frozen comparison

- Evaluate **both** WI_1 and TX_3. Report both even if either actor loses. Load coefficients, SKU order, selected rule settings, and economics directly from each committed bundle. Their model SHA-256 values are respectively `71ac12c3f3ddf294f7070cf2843d0b89b7202a33f395eca026455df923a18117` and `f7abb861d378a6eecc557a3a371ad2de726a32fee1b0ef093a57bde7ed9755e5`. No new candidate search, retraining, or store/SKU selection.
- Download only the official M5 `sales_train_evaluation.csv` from the [Zenodo M5 record](https://zenodo.org/records/10203108) or the [Kaggle M5 data page](https://www.kaggle.com/competitions/m5-forecasting-accuracy/data). Require 1941 consecutive daily columns and the Zenodo file MD5 `b806dfc9f30a745102b708c09951f6aa`. Record its SHA-256. Compare each selected item's days 1–1913 in that file byte-for-byte as integers with the existing `sales_train_validation.csv` (SHA-256 `f368e66ed1dbecb48b2cc8fc589bf68b3deddbbb36bf5c88b4d6d0a09b9b6724`). Abort on a mismatch.
- Replay each frozen actor and its **own frozen validation-selected rule** continuously from zero-based day 1800 through 1940 (M5 days 1801–1941), then score **only** the tail `[1913, 1941)` (M5 days 1914–1941). Each policy carries its own inventory and pipeline state from the already reported 113-day period into the new 28 days. Before revealing any new-period metric, require every warm-up daily profit on days 1801–1913 to match its original published report. Preserve the same per-store SKU order, 0/4/8/16 order packs, shared budget/capacity allocator, lead times and synthetic economics.
- Report actor and rule total simulated profit, paired difference and percent of rule profit, 7-day circular moving-block bootstrap 95% interval (fixed seed 2026, 2000 replicates), fill rate, mean daily spend, 10th-percentile daily profit, and full paired daily profit series. Do not use the new period to change a bundle or release decision. The historical bundles remain an offline research prototype regardless of the result.

## Interpretation

The new 28 days test the **previously frozen** policies on a later calendar period. They are shorter than the earlier 113-day periods and share calendar conditions across stores. The paired interval only reflects within-period daily variation; it does not cover model-design iteration, demand censoring, synthetic economics or deployment risk. A win does not imply real Walmart profit; a loss must be displayed with equal prominence. Prior WI_1 frozen transfer failures and economic stress results remain part of the project record.
