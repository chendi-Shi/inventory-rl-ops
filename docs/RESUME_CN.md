# 简历与面试表述（中文）

**项目名称：** 多 SKU 库存补货的强化学习评估与安全回退平台

可直接放在简历的两条经历：

- 基于 M5 零售销售数据构建 64 SKU、共享采购预算与仓容约束的库存决策环境；实现共享网络 Double DQN、可行动作分配、按时间切分的训练/验证/测试流程，以及 FastAPI 批量决策接口。
- 在五家门店评估纯 RL、基线加 RL 残差及规则引导探索，对比验证集调优的补货规则，并使用配对 7 日块自助法与服务水平门禁做发布决策。候选策略均未达到上线标准，系统自动回退至规则策略；公开完整报告、测试和 CI，不宣称未经证实的利润提升。

**面试中应主动解释：** 这是可复现的决策系统研究原型，不是已经接入 ERP 的生产系统。M5 提供历史销售而非真实未满足需求；库存、采购成本、交货期与预算均为模拟设定。CA_4 的残差策略在验证期仅比规则高 89.05 个模拟单位，在独立测试期低 0.16%。借鉴开源库存项目设计的规则引导探索在 TX_1 验证期胜出，但测试期低 0.14%；未引导模型高 0.06%，置信区间跨零。TX_2 的预算分配权重试验在验证期选回旧规则。这说明新增方法没有取得稳定优势。发布门禁拒绝这些策略，API 默认返回规则订单。

**下一步：** 使用真实库存、缺货、价格与供应商交期记录校准模拟器；增加更多门店和时间原点，与 `(s,S)`、混合整数规划等运筹学方案比较；在影子模式中记录人工覆盖、漂移和服务水平，再考虑受控上线。

不要把模拟利润写成实际业务利润，也不要写“强化学习提升收益”。完整证据见 [三门店结果](CROSS_STORE_RESULTS.md)、[CA_4 残差策略结果](HYBRID_RESULTS.md)、[TX_1 引导探索结果](GUIDED_EXPLORATION_RESULTS.md)、[TX_2 分配权重结果](ALLOCATION_RESULTS.md)及各自的机器可读报告。
